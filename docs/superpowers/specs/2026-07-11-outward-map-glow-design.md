# 地图外扩柔光设计

日期：2026-07-11
状态：已确认，待实施计划

## 背景

当前地图通过叠加多条 `LineMaterial` 宽线模拟辉光。增大宽度和强度时，结果更接近加粗描边，而不是从模型边缘照亮周围空间的柔光。根因是宽线只有固定透明度，没有屏幕空间模糊和连续衰减。

本设计用独立遮罩和多级模糊合成替换宽线辉光，同时保留现有清晰亮芯、内部区界、hover 抬升和材质高亮。

## 已确认的视觉方向

- 辉光主要向地图或区块轮廓外侧扩散。
- 采用“B3：长尾外溢”衰减：近端边缘更柔，远端尾光更明显。
- 扩散半径采用 CSS 屏幕像素，镜头缩放、旋转和容器尺寸变化时保持视觉宽度稳定。
- 常态地图外圈和当前 hover 区块共用真实模糊能力，但参数相互独立。
- 清晰亮芯不参与模糊，扩大柔光范围不能再次形成粗白边。

## 目标

1. 生成从轮廓向外平滑衰减的真实柔光，而不是宽线描边。
2. 让扩散半径和整体透明度可在现有调试抽屉中实时调整。
3. 仅让目标轮廓发光，不影响地图纹理、内部区界、标记和页面其他元素。
4. 常态外圈与 hover 区块使用一致的视觉语言和渲染管线。
5. 在当前约 680 × 680 的地图画布上维持接近现有的帧率与交互响应。

## 非目标

- 不修改柱状图、标记、tooltip、点击下钻或地图数据。
- 不引入整场景 Bloom，也不让地图材质和其他亮色元素进入辉光。
- 本次不固化新的非零辉光默认值；真实地图调试完成后再根据复制的 JSON 单独固化。
- 不重新使用多条宽线作为失败降级辉光。

## 方案选择

采用“独立遮罩 + 多级模糊合成”。

未采用 Selective Bloom，因为它默认向轮廓内外对称扩散，额外遮罩后仍较难隔离透明背景和其他高亮材质。未采用距离场 Shader，因为轮廓距离场生成、转角处理和动态 hover 区域支持超出本次所需复杂度。

## 渲染架构

### 主场景

主场景继续渲染：

- 地图挤出模型与地形纹理；
- 内部区界；
- 常态外圈清晰亮芯；
- hover 区块清晰亮芯；
- hover 抬升、顶面颜色与自发光动画。

主场景中的清晰亮芯不进入模糊缓冲。

### 辉光源遮罩

渲染管线分别维护两个单通道遮罩：

- 常态遮罩：只包含地图整体最外轮廓；
- hover 遮罩：只包含当前 hover 区块轮廓。

遮罩不包含内部区界、地图纹理、标记或其他页面元素。hover 目标改变时替换 hover 遮罩内容；无 hover 目标时不执行 hover 模糊与合成。

### B3 多级模糊

每个启用的遮罩生成两层柔光：

- 近端层：模糊半径约为配置扩散半径的 35%，使用相对较低透明度；
- 远端层：使用完整扩散半径，并保留更高的长尾透明度。

两层使用可分离 Gaussian Blur 或等效的多次 Kawase Blur。实现阶段优先选择在当前 Three.js 版本下通道数更少、半分辨率表现更稳定的实现；两者必须满足同一输入输出契约和验收标准。

### 外侧裁切与合成

模糊结果与对应区域的实心遮罩组合，只保留轮廓外侧像素。边界附近保留一个极窄的软过渡，避免硬裁切形成锯齿或断层。

常态与 hover 柔光分别乘以各自颜色和透明度后，以加法或预乘透明度兼容的屏幕合成方式叠加到主场景。合成必须保持 WebGL 画布现有透明背景行为。

渲染顺序为：

1. 更新必要的常态或 hover 遮罩；
2. 生成近端与远端模糊；
3. 渲染主场景；
4. 裁切并合成常态柔光；
5. 裁切并合成 hover 柔光。

## 屏幕像素换算

配置中的扩散半径单位为 CSS px。Shader 的纹理采样步长根据以下状态换算：

- 容器 CSS 尺寸；
- RenderTarget 实际像素尺寸；
- `window.devicePixelRatio`；
- 项目现有 `ScaleScreen` 页面缩放；
- 模糊缓冲分辨率比例。

Resize、DPR 或 `ScaleScreen` 改变时更新缓冲尺寸和换算系数。OrbitControls 改变相机时只更新遮罩内容，不改变 CSS px 对应的视觉扩散半径。

## 参数与调试抽屉

继续使用 `version: 1` 和现有 JSON 字段，不增加迁移：

| 字段 | 控件名称 | 新语义 | 范围 |
| --- | --- | --- | --- |
| `base.outerGlowWidth` | 外圈扩散半径 | 常态外圈最远扩散距离，CSS px | 0–120，步长 1 |
| `base.outerGlowStrength` | 外圈辉光透明度 | 常态柔光整体透明度 | 0–1，步长 0.01 |
| `hover.glowWidth` | Hover 扩散半径 | 当前区块最远扩散距离，CSS px | 0–120，步长 1 |
| `hover.glowStrength` | Hover 辉光透明度 | 完整 hover 状态的柔光透明度 | 0–1，步长 0.01 |

颜色字段继续控制对应柔光颜色。hover 透明度继续乘以现有 eased hover 进度，`enterMs` 与 `leaveMs` 保持有效。

B3 的两层比例固定在渲染器内部，不向调试面板暴露近端/远端底层参数。真实地图的首轮参考调试值为扩散半径约 54 px、透明度约 0.23，但已提交的默认值继续保持为 0，直到用户复制并确认新参数。

## 更新与缓存策略

- 常态遮罩在地图构建、相机变化或容器尺寸变化时标记为脏；常态扩散半径变化只重新执行模糊。
- hover 遮罩在 hover 目标变化、相机变化或容器尺寸变化时标记为脏。
- 仅透明度动画变化时复用已有模糊纹理，在合成阶段调整透明度。
- 半径变化时重新执行对应模糊；颜色和透明度变化不重新生成遮罩。
- 半径或透明度为 0 时跳过对应的遮罩、模糊与合成步骤。

## 性能与资源生命周期

- 遮罩与模糊 RenderTarget 默认使用画布宽高的 50%。
- 常态与 hover 共用 ShaderMaterial、全屏三角形和 ping-pong 临时缓冲；最终结果纹理分别保存。
- 模糊实现不得在动画帧中创建新的材质、几何体、纹理或数组规模对象。
- 若高 DPR 设备无法维持目标帧率，可把模糊缓冲降为 25%，同时补偿采样半径，使 CSS px 视觉尺度不变。
- 组件卸载时释放 RenderTarget、ShaderMaterial、纹理与全屏几何体；重新进入页面不得累积 WebGL 资源。

## 降级与错误处理

- 遮罩、RenderTarget 或 Shader 初始化失败时，地图主体和交互继续工作。
- 降级状态保留常态和 hover 清晰亮芯，并关闭真实柔光。
- 失败只输出一次包含阶段信息的警告，避免每帧刷屏。
- 不回退到现有多宽线辉光，因为该效果不满足本设计目标。

## 测试策略

### 单元测试

- CSS px 到纹理采样半径的换算；
- B3 近端与远端半径、透明度比例；
- 半径或透明度为 0 时的短路；
- hover eased 进度对最终透明度的影响；
- dirty 状态在相机、尺寸、目标和参数变化时正确更新。

### 组件与集成测试

- 管线初始化并按正确顺序调用遮罩、模糊、主场景与合成；
- Resize、DPR 与 `ScaleScreen` 更新 RenderTarget 和采样参数；
- 常态参数和 hover 参数热更新互不污染；
- hover 区块切换和离开后不残留上一目标的柔光；
- 初始化失败时保留地图主体、清晰亮芯、hover 抬升和交互；
- 卸载时所有新增 WebGL 资源只释放一次。

### 浏览器验收

- 在真实地图上，扩大半径表现为更大范围的柔光，而不是更粗的白边；
- 柔光主要位于轮廓外侧，地图内部不出现同等强度的泛白；
- 常态外圈和 hover 区块都呈现 B3 的近柔远长尾特征；
- 镜头缩放、旋转和容器缩放后，扩散范围保持稳定的屏幕像素宽度；
- 内部区界、柱状图、标记和页面面板不被带入辉光；
- 调试抽屉复制的 JSON 重新载入后能复现相同效果；
- 当前目标设备与页面尺寸下，开启参考值后交互保持流畅且无持续控制台错误。

## 验收标准

1. 将扩散半径从 20 px 调到 60 px 时，清晰亮芯宽度保持不变，外侧柔光范围明显扩大。
2. 将透明度从 0.1 调到 0.4 时，扩散范围不改变，只改变光的可见强度。
3. 常态和 hover 的半径、颜色、透明度及动画互相独立。
4. 半径或透明度为 0 时无柔光，且不执行对应后处理步骤。
5. 当前功能测试、类型检查和生产构建通过；新增视觉行为通过真实页面验证。
